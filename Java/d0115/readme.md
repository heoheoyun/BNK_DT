# 🛠️ 핵심 기술 역량

## 제네릭(Generic) 프로그래밍
- 타입 매개변수(`<T>`)를 활용한 타입 안전성 확보 및 코드 재사용성 극대화
- 컴파일 타임에 타입 체크를 수행하여 `ClassCastException` 런타임 에러 방지
- 제네릭 클래스(`InfinityArray<T>`)와 제네릭 메소드(`<T>void printArray(T[] t)`) 구현
- 타입 소거(Type Erasure)를 고려한 `Object[]` 기반 내부 구조 설계 및 안전한 다운캐스팅(`(T)`) 적용

## 컬렉션 프레임워크(Collection Framework) 활용
- `ArrayList<E>`의 핵심 메소드 학습 및 실무 적용
  - 추가: `add()`, `add(index, element)`
  - 조회: `get()`, `getLast()`, `size()`, `isEmpty()`
  - 수정: `set()`
  - 삭제: `remove(index)`, `remove(object)`
  - 검색: `contains()`, `indexOf()`, `lastIndexOf()`
- 동적 배열의 장점을 활용한 유연한 데이터 관리

## 자료구조 직접 구현 (커스텀 컬렉션)
- `ArrayList`와 유사한 기능을 가진 `InfinityArray<T>` 제네릭 클래스 구현
- 배열 확장 시 새로운 배열 생성 후 기존 데이터 복사 로직 구현
- 중간 삽입/삭제 시 인덱스 재배치 알고리즘 설계
- `toString()` 메소드 재정의로 배열 내용을 직관적으로 출력

## 게시판 CRUD 시스템 설계
- **데이터 모델**: `Board` 클래스로 게시글(번호, 제목, 내용, 작성자) 표현
- **데이터베이스 계층**: `BoardDB` 클래스에서 `ArrayList<Board>`로 게시글 저장소 관리
- **비즈니스 로직**: `BoardCRUD` 클래스에서 삽입, 조회, 수정, 삭제 기능 분리
- **검색 최적화**: 번호, 제목, 내용, 작성자 등 다양한 조건으로 게시글 검색 가능
- **객체 동등성**: `equals()` 재정의로 게시글 비교 로직 구현

# 📂 주요 실습 프로젝트 (d0115)

## 1. 제네릭 배열 프린터 (`ArrayPrinter.java`)
- **제네릭 메소드 구현**: `static <T>void printArray(T[] t)` 메소드로 모든 타입의 배열을 출력
- **타입 안전성**: `Integer[]`, `Float[]`, `Double[]`, `String[]` 등 다양한 타입의 배열을 하나의 메소드로 처리
- **코드 재사용**: 타입별로 메소드를 중복 작성할 필요 없이 제네릭으로 통합

## 2. ArrayList 실습 (`ArrayListTest.java`)
- **기본 조작**: 요소 추가, 삭제, 수정, 조회를 통한 동적 배열 관리
- **특정 위치 삽입**: `add(1, "배")`로 중간에 요소를 삽입하면 기존 요소들이 자동으로 뒤로 이동
- **중복 허용**: `ArrayList`는 동일한 요소의 중복 저장을 허용하며, `indexOf()`와 `lastIndexOf()`로 첫 번째/마지막 위치 확인
- **순회 방법**: 일반 `for`문과 향상된 `for-each`문 두 가지 방식으로 배열 순회

## 3. 제네릭 무한 확장 배열 (`InfinityArray<T>`)
- **핵심 기능 구현**:
  - `add(T obj)`: 배열 끝에 요소 추가
  - `add(int idx, T obj)`: 특정 위치에 요소 삽입 후 기존 요소 재배치
  - `remove(int idx)`: 특정 인덱스 요소 삭제 후 배열 크기 축소
  - `remove(T obj)`: 객체로 요소 찾아 삭제
  - `get(int idx)`: 특정 위치 요소 반환 (제네릭 타입으로 안전한 캐스팅)
  - `set(int idx, T obj)`: 특정 위치 요소 수정
  - `contains(T obj)`: 특정 요소 존재 여부 확인
  - `indexOf(T obj)` / `lastIndexOf(T obj)`: 요소의 위치 검색
- **동적 배열 관리**: 요소 추가 시 배열 크기를 1씩 증가시키고, 삭제 시 1씩 감소
- **인덱스 재배치 로직**: 중간 삽입/삭제 시 기존 데이터를 새 배열로 복사하며 인덱스를 조정

## 4. 게시판 시스템 (`Board` / `BoardDB` / `BoardCRUD`)
- **데이터 계층 분리**:
  - `Board`: 게시글 엔티티 (번호는 `static` 카운터로 자동 증가)
  - `BoardDB`: `ArrayList<Board>`로 게시글 저장소 관리
  - `BoardCRUD`: 비즈니스 로직 담당 (삽입, 조회, 수정, 삭제)
- **CRUD 구현**:
  - **Create**: `insert()` - 게시글을 DB에 추가
  - **Read**: `selectList()` - 전체 게시글 목록 출력, `select()` - 조건별 게시글 검색
  - **Update**: `modify()` - 기존 게시글을 새 게시글로 교체
  - **Delete**: `delete()` - 게시글 삭제
- **다중 조건 검색**: `select(db, int select, Object obj)` 메소드로 번호(1), 제목(2), 내용(3), 작성자(4) 기준 검색
- **객체 비교**: `equals()` 재정의로 게시글의 모든 필드를 비교하여 동등성 판단

# 📝 실습 회고

## 제네릭의 강력함
타입 매개변수를 사용하여 하나의 클래스나 메소드로 여러 타입을 처리할 수 있는 제네릭의 장점을 직접 체감함. `InfinityArray<T>`와 `ArrayPrinter<T>` 구현을 통해 코드 중복을 제거하고 타입 안전성을 확보하는 방법을 학습함

## ArrayList의 내부 동작 이해
직접 `InfinityArray`를 구현하면서 `ArrayList`의 내부 메커니즘(배열 복사, 인덱스 재배치, 동적 크기 조정)을 깊이 이해하게 됨. 단순히 API를 사용하는 것을 넘어 자료구조의 원리를 체득함

## 계층 분리의 중요성
게시판 시스템을 구현하며 데이터 계층(`BoardDB`), 비즈니스 로직 계층(`BoardCRUD`), 엔티티 계층(`Board`)을 분리하는 설계 패턴을 학습함. 각 계층의 책임이 명확히 분리되어 유지보수성과 확장성이 향상됨을 경험함

## 컬렉션 프레임워크의 실용성
배열의 고정 크기 한계를 극복한 `ArrayList`의 강력함을 실습을 통해 확인함. 중복 허용, 동적 크기 조정, 다양한 검색 메소드 등 실무에서 바로 활용 가능한 기능들을 익힘

## 객체 비교와 검색 로직
`equals()` 재정의와 `indexOf()` 구현을 통해 객체 간 동등성 비교의 중요성을 다시 한번 체감함. 특히 `contains()`와 `remove(Object)` 같은 메소드가 내부적으로 `equals()`를 사용한다는 점을 이해하며 올바른 재정의의 필요성을 깨달음
