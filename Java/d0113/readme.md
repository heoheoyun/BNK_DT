# 🛠️ 핵심 기술 역량

## 인터페이스 기반 다형성 및 확장
- `TV` 인터페이스를 통해 브랜드에 독립적인 제어 환경 구축
- `multifunctionable` 인터페이스로 `Printable`, `Copyable`, `Scanable`을 통합하여 다중 기능 객체(`NewPrinter`) 설계

## 팩토리 디자인 패턴(Factory Pattern)
- `TVFactory` 및 `PrinterFactory`를 도입하여 클라이언트 코드가 구체적인 구현 클래스(`Stv`, `Ltv`, `HPPrinter` 등)에 의존하지 않도록 객체 생성 로직을 캡슐화

## 객체 동등성 및 해시 데이터 관리
- `equals()`와 `hashCode()`를 재정의하여 메모리 주소가 아닌 실제 필드 값을 기준으로 객체를 비교하도록 구현
- `Objects.hash()`를 사용하여 데이터 일관성 확보

## 동적 데이터 관리 시스템
- `Manageable` 인터페이스를 통해 CRUD(등록, 조회, 수정, 삭제) 표준 규격 정의
- 배열이 가득 찼을 때 크기를 늘리는 `expand()` 메소드를 통한 수강생 및 직원 데이터의 동적 관리

# 📂 주요 실습 프로젝트 (d0113)

## 1. TV 및 프린터 제어 시스템
- **인터페이스 표준화**: `powerOn`, `volumeUp` 등 모든 제조사가 공통으로 가져야 할 기능을 정의하여 결합도를 낮춤
- **디폴트 메소드 활용**: `Printable` 인터페이스 내에 `default` 키워드로 `showEndMessage()`를 구현하여 하위 클래스에서 공통 로직을 재사용

## 2. 학원 통합 관리 시스템 (`Academy.java`)
- **표준 관리 규격**: `StudentManagement`와 `EmployeeManagement` 클래스가 `Manageable` 인터페이스를 구현하여 관리 일관성 유지
- **비즈니스 로직**:
  - **등록**: 고유 번호 부여 및 배열 동적 확장
  - **조회/수정**: 번호, 이름, 전화번호 등 다양한 조건별 검색 및 필드 업데이트
  - **삭제**: 임시 객체를 생성하고 재정의된 `equals()`를 호출하여 논리적 일치 여부를 판단한 뒤 데이터 제거

## 3. Object 메소드 재정의 실습
- **equals() 3단계 구현**: 자기 참조 확인(`this == obj`), 타입 체크(`instanceof`), 필드 값 비교의 절차를 준수하여 구현
- **데이터 무결성**: 논리적으로 동일한 객체는 동일한 해시코드를 가져야 한다는 원칙을 실무 코드로 적용

# 📝 실습 회고

## 유연한 설계의 이점
팩토리 패턴과 인터페이스를 조합함으로써, 새로운 브랜드(예: Sony TV)가 추가되어도 기존 사용자 코드(`TvUser`)를 수정할 필요가 없는 확장성을 경험함

## 다중 상속의 보완
자바의 단일 상속 한계를 인터페이스 간 상속(`extends Printable, Copyable...`)으로 해결하여 복합기 같은 복합 객체를 효과적으로 모델링함

## 자료구조의 이해
배열을 이용한 CRUD 구현 과정에서 인덱스 관리와 객체 비교 로직의 중요성을 다시 한번 체감함
